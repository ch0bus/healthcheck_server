Итоговая работа по удалению io.elementary.appcenter

Проблема: Процесс io.elementary.appcenter занимал ~12,8% памяти (~1 ГБ) и замораживал систему.

Решение: Полное удаление пакета pop-shop и завершение процесса.
Команды для диагностики и устранения подобных проблем
Шаг 1: Поиск процессов, потребляющих много ресурсов
Команда	Описание
ps aux --sort=-%mem | head -15	Список процессов отсортирован по потреблению памяти (от большего к меньшему)
ps aux --sort=-%cpu | head -15	Список процессов отсортирован по потреблению CPU
top -b -n 1 | head -20	Интерактивный вид потребления ресурсов (non-interactive mode)
htop	Интерактивный монитор (если установлен)
Шаг 2: Определение источника процесса
Команда	Описание
which <процесс>	Найти путь к исполняемому файлу (например, which io.elementary.appcenter)
dpkg -S /путь/к/файлу	Определить, какому пакету принадлежит файл (например, dpkg -S /usr/bin/io.elementary.appcenter)
apt show <пакет>	Получить информацию о пакете (версия, описание, maintainer)
Шаг 3: Анализ зависимостей
Команда	Описание
apt-cache depends <пакет>	Список прямых зависимостей пакета (что нужно ему)
apt-cache rdepends <пакет>	Список обратных зависимостей (что зависит от него)
apt-cache rdepends --no-recommends <пакет>	Обратные зависимости без рекомендаций
Шаг 4: Безопасное удаление
Команда	Описание
sudo apt remove <пакет>	Удалить пакет (сохранить конфиги)
sudo apt purge <пакет>	Полностью удалить пакет (включая конфиги)
sudo apt autoremove	Удалить ненужные зависимости
sudo apt clean	Очистить кэш пакетов
Шаг 5: Завершение процесса
Команда	Описание
kill <PID>	Мягко завершить процесс (сигнал SIGTERM)
kill -9 <PID>	Принудительно завершить процесс (сигнал SIGKILL)
sudo kill <PID>	Завершить процесс от root (если нужно)
killall <имя_процесса>	Завершить все процессы по имени
Шаг 6: Проверка автозапуска
Команда	Описание
systemctl --user list-unit-files | grep enabled	Список enabled служб пользователя
systemctl list-unit-files | grep enabled	Список enabled системных служб
systemctl --user status <служба>	Статус пользовательской службы
systemctl status <служба>	Статус системной службы
systemctl --user disable <служба>	Отключить автозапуск пользовательской службы
sudo systemctl disable <служба>	Отключить автозапуск системной службы
Бонус: Полная диагностика в одной команде
bash

# Найти все процессы, потребляющие более 5% памяти
ps aux | awk '$4 > 5 {print $2, $4"%", $11}' | sort -k2 -rn

bash

# Быстрая диагностика процесса
PROC="io.elementary.appcenter"
echo "=== Процесс ===" && which $PROC
echo "=== Пакет ===" && dpkg -S $(which $PROC)
echo "=== Зависимости ===" && apt-cache rdepends $(dpkg -S $(which $PROC) | cut -d: -f1)

Практический алгоритм для будущего

    Выявить тяжёлый процесс: ps aux --sort=-%mem | head -15
    Найти его источник: which <процесс> → dpkg -S <путь>
    Проверить зависимости: apt-cache rdepends <пакет>
    Оценить важность: нужен ли этот пакет системе?
    Удалить: sudo apt remove <пакет>
    Убить остаток: kill <PID> (если процесс ещё запущен)
    Очистить: sudo apt autoremove && sudo apt clean
    Проверить автозапуск: systemctl --user list-unit-files | grep <пакет>

В вашем случае: pop-shop был удачным кандидатом на удаление, так как это non-critical магазин приложений, а не системный компонент. pop-desktop — это только meta-пакет, поэтому его удаление не повредило системе.
